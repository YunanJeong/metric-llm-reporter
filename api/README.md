# HTTP API (선택 계층)

기존 셸 파이프라인을 **그대로 두고** HTTP로 호출할 수 있게 감싼 레이어입니다.
`run.sh` / cron 방식은 아무 영향을 받지 않으며, 이 디렉터리를 지워도 원래 도구는 그대로 동작합니다.

## 설계 원칙

- **로직 중복 없음**: 메트릭 수집·LLM 분석 로직은 `1.fetch.sh` / `2.brain.sh`에 그대로 두고,
  API는 `subprocess`로 호출만 합니다. 수집 쿼리나 프롬프트를 바꿀 일이 생기면 여전히 셸 스크립트 한 곳만 고칩니다.
- **비동기 작업(job)**: LLM 분석은 수십 초~수 분이 걸리므로 요청을 즉시 `202 Accepted` + job id로 받고
  결과는 폴링으로 가져갑니다. LLM 호출은 동시 1건으로 제한(초과 시 `409`)해 모델·API 쿼터를 보호합니다.
- **입력 제한**: 환경변수 파일은 저장소 루트의 `*.env` 파일명만 허용합니다(경로 조작 및 임의 파일 로드 차단).
  셸을 경유하지 않고(`shell=True` 미사용) 인자로만 전달합니다.
- **오류 응답에 내부 정보 미포함**: 스크립트의 stderr에는 내부 URL·자격증명이 섞일 수 있어
  서버 로그에만 남기고 응답에는 종료 코드 수준의 메시지만 반환합니다.
- **메일 발송은 제외**: 외부로 나가는 부작용이라 API 표면에 두지 않았습니다. 발송은 `run.sh`/cron 담당입니다.

## 실행

```bash
# 의존성 설치 없이 바로 실행 (PEP 723 인라인 메타데이터)
uv run api/main.py

# 문서: http://127.0.0.1:8000/docs
```

기본 바인딩은 `127.0.0.1:8000`입니다. 자격증명이 담긴 `*.env`를 지정해 파이프라인을 실행시키는 API이므로
외부에 그대로 노출하지 말고, 필요하면 리버스 프록시에서 인증을 붙이십시오.

## 엔드포인트

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/healthz` | 헬스체크 |
| `GET` | `/v1/metrics?env=0.env&refresh=false` | 압축 메트릭 리포트 (`1.fetch.sh`). 기본 60초 TTL 캐시 |
| `POST` | `/v1/analyses` | LLM 분석 실행 요청 → `202` + job |
| `GET` | `/v1/analyses` | 최근 job 목록 (최대 50건) |
| `GET` | `/v1/analyses/{job_id}` | job 상태·결과 조회 |

```bash
curl -s localhost:8000/v1/metrics | jq -r .report

JOB=$(curl -s -X POST localhost:8000/v1/analyses \
        -H 'content-type: application/json' -d '{"env":"0.env"}' | jq -r .id)
curl -s localhost:8000/v1/analyses/$JOB | jq -r '.status, .analysis'
```

## 한계

- job 저장소와 캐시는 **프로세스 메모리**입니다. 재시작하면 사라지고, 워커를 여러 개 띄우면 공유되지 않습니다.
  단일 프로세스 운용을 전제로 합니다(여러 워커가 필요해지면 job 저장소를 외부로 빼야 합니다).
- 인증·레이트리밋은 없습니다. 로컬/내부망 전용입니다.
